## 1. 한국어 작성 지침
- 한국어 설명이나 문서 본문을 작성하기 전에 Codex 홈에 있는 `korean_style.md`를 읽고 적용합니다.
- Codex 홈은 환경 변수 `CODEX_HOME`이 설정되어 있으면 그 경로이고, 설정되어 있지 않으면 사용자 홈의 `.codex`입니다. 현재 작업 디렉터리에서 찾지 않습니다.
- 컨텍스트가 압축되어 `korean_style.md`의 내용이 남아 있지 않으면 다시 읽습니다.
- 사용자가 한국어 지침에 대한 수정안을 제시하면, 이해한 수정 사항을 설명하고 `[수정 전 → 수정 후]` 형식의 예시 2개를 제시한 뒤 `korean_style.md`에 기록할지 묻습니다.

## 2. 명령의 실행 환경
- 모든 명령 블록에 실행 환경을 표시합니다. Windows PowerShell과 macOS, Linux Bash 또는 필요한 가상환경을 구체적으로 밝힙니다.

## 3. 스크립트의 출력과 주석을 구분
- 스크립트의 출력 문자열과 오류 메시지는 영어로 작성합니다. 주석과 docstring은 한국어로 작성합니다.
- 기존 프로젝트의 명시적인 규칙이나 기존 파일의 관례가 이 조항과 다르면, 어느 쪽을 따를지 사용자에게 확인합니다. 확인한 결과는 같은 세션에서 계속 적용합니다.

## 4. 대대적인 변경의 범위와 결과를 설명
- 만들거나 변경할 파일과 시스템에 생기는 변화 및 얻을 결과를 설명합니다. 사용자가 생성이나 수정 및 실행을 명시적으로 요청한 범위는 승인된 작업으로 처리합니다.
- 범위를 벗어나는 대대적인 변경에는 검증 결과를 보고하고 사용자의 선택을 확인합니다.
- 사용자가 직접 실행할 때는 복사하여 사용할 수 있는 명령과 파일 내용을 제공합니다. 자동 실행이 승인되면 실행하고 결과를 보고합니다.

## 5. 삭제 여부는 사용자가 판단
- 정리 작업에서는 각 항목의 정체와 크기 및 최종 수정일과 참조 여부 및 중복 여부를 조사합니다.
- 선택지를 제시하고 사용자가 명시적으로 지시한 항목만 삭제합니다.

## 6. 줄바꿈을 저장소에서 관리
- `.gitattributes`의 기본값은 `* text=auto eol=lf`로 유지합니다.
- Windows 전용 파일에는 필요한 CRLF 예외를 지정합니다.
- 만약 Windows PowerShell 5.1에서 한글을 포함한 스크립트를 읽어야 하면 UTF-8 BOM도 적용합니다.

## 7. Python 이름을 일관되게 정함
- 새로 만드는 Python 배포판 이름과 import 이름은 동일하게 정합니다. Python 모듈과 패키지 이름에는 하이픈을 사용하지 않습니다.

## 8. 피드백을 관리
- 사용할 수 있는 메모리 기능이 있으면 사용자가 지적한 피드백을 기록합니다.
- 이번 세션에서 저장된 피드백이 무엇인지 요청하거나 공통 지침에 올릴 만한 사항을 묻는 요청이 발생하면 피드백에 번호를 매겨 정리하고 공통 지침에 반영하는 것을 제안합니다.

## 9. 메모리 갱신 내용을 요약
- 메모리 기능이 제공되는 환경에서 기록을 추가하거나 정정했다면 바뀐 내용을 보고합니다. 사용자가 묻지 않으면 경로와 파일명 및 수정 전후 원문을 나열하지 않습니다. 지원 여부와 저장 위치를 확인하지 않고 다른 도구의 메모리 경로를 그대로 사용하지 않습니다.
